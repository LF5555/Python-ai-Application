# チェック項目（Streamlit + LLM + API アプリ用）

各項目は「何を見るか → どう確かめるか → 危険度の目安」の順に書いてある。
アプリごとに作りが違うので、当てはまらない項目は「該当なし（理由）」として報告し、無理に問題を作らない。
危険度は「誰が使うか（自分だけ / LAN / インターネット公開）」で変わる。SKILL.md の手順 1 で確認した前提に合わせて決める。

コマンド例は Windows の PowerShell 用（`&&` は使えない）。パスに日本語やスペースが入ることがあるので `"` で囲む。
`<skill>` はこのスキルのフォルダ（`SKILL.md` がある場所）を表す。

## 0. 全体像をつかむ

最初に次を確認し、どの項目が関係するかを決める。
- 入口のファイル（`streamlit run` するファイル）と `pages/` フォルダ（マルチページ）の有無
- 使っている LLM サービスとライブラリ（`requirements.txt` / `pyproject.toml`、`import` 文）
  - 例: `openai`、`anthropic`、`google-genai` / `google-generativeai`、`langchain`、`requests` で直接 REST を呼ぶ、など
- ツール呼び出し（function calling）、エージェント、RAG（文書を検索して AI に渡す仕組み）、URL の取得、ファイルのアップロードがあるか
- データベースやファイルへの保存があるか
- `.streamlit/` フォルダ（`config.toml`、`secrets.toml`）の有無

## A. 秘密情報（API キー・パスワード）

`.env` と `.streamlit/secrets.toml` は開かない（`cat`・`Get-Content`・Python から読むのも含む）。
変数名は `.env.example` などのひな形や、コード中の `os.getenv(...)` / `st.secrets[...]` から調べる。

1. **直書き・履歴・追跡状態**: `python "<skill>\scripts\scan_secrets.py"` をプロジェクトのフォルダで実行する。
   - `.env` や `secrets.toml` が「追跡中」「無視されていない」「過去にコミットされた」に出たら **高**。
     過去にコミットされていたら、履歴から消すだけでは不十分で、キーの作り直し（古いキーの無効化）が必要と伝える。
   - コードに本物らしいキーがあれば **高**。候補は機械的な一致なので、該当行を読んで本物か判断する。
   - git 管理でないフォルダではスクリプトが止まる。その場合は `Grep` で同じ種類の文字列を探し、「git の履歴は確認していません」と書く。
2. **`.gitignore`**: `.env`、`.streamlit/secrets.toml`、`.venv/` が入っているか（`git check-ignore -v <ファイル>`）。
3. **キーの渡し方**: キーを URL のクエリ（`?key=...`）に入れていないか。入っていると、`requests` などの例外メッセージに URL ごと出て、画面やログに漏れることがある → **中**。ヘッダーで送るのが望ましい。
4. **画面に出る経路**:
   - 例外をそのまま `st.error(f"...{e}")` / `st.exception(e)` / `st.write(e)` に出している箇所を探し、その例外にキー・トークン・アカウント ID が混ざる可能性を読む。
   - 設定値をデバッグ表示していないか（`st.write(os.environ)`、`st.write(st.secrets)`、`st.json(config)` など）→ あれば **高**。
   - キーを `st.text_input` の初期値に入れていないか（画面の HTML に出る）→ **高**。
5. **ログ**: `print(`、`logging`、LLM ライブラリのデバッグ出力で、キーやリクエスト全体を出していないか。

## B. 認証・アクセス制御

1. **認証の有無と方式**: 次のどれかを確認する。
   - なし / 自作のパスワード画面 / `st.login()`（Streamlit 1.42 以降の OIDC ログイン）/ ホスティング側の認証（Community Cloud の閲覧者制限など）/ リバースプロキシの Basic 認証
   - インターネット公開で認証なしなら **高**（他人があなたのキーで AI を使える）。自分の PC だけなら **情報**。
2. **自作ログインの場合**:
   - パスワードを `hmac.compare_digest` など一定時間比較で比べているか。`==` なら **低**。
   - パスワードがコードに直書きされていないか（A で検出）。
   - ログイン判定と `st.stop()` が、API 呼び出し・データ表示・サイドバーより**前**にあるか。ログイン前に LLM や API が呼ばれるなら **中〜高**。
   - 失敗しても何回でも試せるか。インターネット公開なら **中**、それ以外は **低**。
3. **マルチページ（`pages/` や `st.navigation`）**: 入口のファイルだけでログイン判定していて、他のページを URL で直接開くと素通りできないか。各ページの先頭で判定しているか、`st.navigation` でログイン前はページを出さない作りか → 素通りできるなら **高**。
4. **権限の分け方**: 管理者用の機能（設定変更・全履歴の閲覧など）があれば、一般の利用者から使えないか。
5. **パスワードの強さ**: 値は見ずに、短い・推測しやすい値になっていないかユーザーに確認してもらう。

## C. 公開範囲と Streamlit の設定

`python -I "<skill>\scripts\streamlit_config.py"` を、アプリの仮想環境の Python で実行すると、実際に使われる値が分かる。

1. **`server.address`**: `None`（未設定）だと、起動時に「Network URL」が表示され、同じ Wi-Fi などの他の端末から開ける状態になりうる。
   自分の PC だけで使うなら `.streamlit/config.toml` に `[server]` `address = "127.0.0.1"` を勧める。
   自分だけ → **中**（公衆 Wi-Fi で起動すると他人に見える）、認証なしで LAN に公開 → **高**。
2. **`server.enableXsrfProtection` / `server.enableCORS`**: `False` なら **中**（初期値は両方 `True`）。
3. **`client.showErrorDetails`**: 初期値 `"full"` では、エラーの種類・メッセージ・トレースバック（どのファイルの何行目かの情報）がブラウザに表示される。
   他人に使わせるなら `"type"` か `"none"` を勧める → 公開時 **中**、自分だけなら **情報**。
4. **`server.enableStaticServing`**: `True` なら、`static/` フォルダの中身が誰でも URL で読める。秘密のファイルが置かれていないか → あれば **高**。
5. **`server.maxUploadSize`**: ファイルのアップロードがある場合、初期値 200MB で十分か（G と合わせて判断）→ **低**。
6. **`browser.gatherUsageStats`**: `True` だと Streamlit に利用統計が送られる。内容の詳細は確認していなければ「未確認」と書く → **情報**。
7. **公開先**: Streamlit Community Cloud などに公開しているか、ポート開放・トンネル（ngrok など）を使っているかはユーザーに聞く。
   Community Cloud では、アプリが「公開」設定か「閲覧者を限定」かも確認してもらう。

## D. 画面への表示（HTML・リンク・画像）

AI の出力・ユーザーの入力・外部から取ってきた文章は、信用できない文字列として扱う。

1. `Grep` で `unsafe_allow_html=True|st\.html|components\.html|components\.v1|components\.iframe` を検索する。
   - 使っていなければ問題なし（`st.markdown` の `unsafe_allow_html` は初期値 `False`）。
   - AI の出力・ユーザー入力・外部の文章をそこに渡していたら **高**（悪意ある HTML / JavaScript が動く）。
   - 固定の文字列（自分で書いた CSS など）だけなら問題なし。
2. **Markdown の画像・リンク**: `st.markdown` で AI の出力を表示すると、`![](https://...)` の画像は自動で読み込まれる。
   アプリが外部の文章（アップロードされた文書、Web ページ、メールなど）を AI に読ませる場合、そこに仕込まれた指示で
   「会話の内容を URL に含めた画像」を出力させ、情報を外に送らせる手口がある → 外部の文章を扱うなら **中**、扱わないなら **低**。
3. `st.download_button` / `st.link_button` の URL やファイル名に、検査していない入力が入っていないか → **低**。

## E. LLM 固有のリスク

1. **プロンプトインジェクション**（入力や外部の文章に「これまでの指示を無視して…」などを混ぜ、AI を乗っ取る手口）
   - AI が文章を返すだけなら、影響は「変な文章が出る」程度で **低**。
   - AI がツールを呼べる（ファイル操作、DB 操作、メール送信、Web 取得、コード実行など）なら、乗っ取られたときに何ができるかを洗い出す。
     ユーザーの確認なしに危険な操作ができるなら **高**。
2. **AI の出力をそのまま実行・組み込みしていないか**: `eval` / `exec`、SQL 文、シェルコマンド、ファイルパス、URL に AI の出力を入れていたら **高**。
3. **システムプロンプトに秘密を入れていない**か（キー、社内情報、他の利用者の情報）。システムプロンプトは聞き出せるものと考える → 入っていたら **中〜高**。
4. **RAG・アップロード文書**: 他の利用者の文書が検索結果に混ざらないか（利用者ごとに分けているか）→ 混ざるなら **高**。
5. **出力の長さ**: `max_tokens` などの上限があるか。ない・極端に大きいと料金がかさむ（J と合わせて判断）→ **低**。

## F. 外部 API・通信

1. 接続先 URL が `https://` か。`http://` なら **中**。
2. `verify=False`（証明書の確認を切る設定）がないか → あれば **高**。
3. `timeout=` があるか。なければ **低**（固まるだけで、情報漏れではない）。
4. ユーザーの入力を URL・パスに組み込んでいる箇所:
   - 選択肢が固定・API 由来の selectbox なら **低**。自由入力をそのまま入れていたら **中**。
5. **SSRF**（ユーザーが指定した URL をサーバー側で取りに行く機能を悪用し、内部のネットワークや `localhost`、クラウドのメタデータにアクセスさせる手口）:
   URL を入力して要約するような機能があれば、`http://localhost`、`127.0.0.1`、`192.168.x.x`、`169.254.169.254` などを拒否しているか → 対策なしで公開なら **高**、自分だけなら **低**。

## G. ファイルのアップロードと保存

`st.file_uploader` やファイルの書き込みがある場合だけ確認する。

1. `type=` で拡張子を絞っているか。読み込み処理が危険な形式（`pickle`、`joblib`、マクロ付き Office など）を扱っていないか → **中〜高**。
2. 保存するとき、アップロードされたファイル名をそのままパスに使っていないか（`../` でフォルダの外に書き込まれる）→ **高**。
3. ZIP の展開がある場合、展開後のサイズや中のパスを確認しているか → **中**。
4. 保存したファイルを他の利用者が見られないか → 見られるなら **高**。

## H. キャッシュとセッション（利用者どうしの混線）

Streamlit では `st.session_state` は利用者（ブラウザのセッション）ごとだが、**`st.cache_data` と `st.cache_resource` はすべての利用者で共有される**。

1. `st.cache_data` / `st.cache_resource` を付けた関数が、利用者ごとのデータ（会話・アップロード文書・個人情報・その人の API キーで取った結果）を返していないか → 複数人で使うなら **高**、自分だけなら **情報**。
2. モジュールの一番外側の変数（グローバル変数）に利用者ごとのデータを入れていないか（これも全員で共有される）→ 同上。
3. 利用者が自分の API キーを入力する作りなら、そのキーが `st.session_state` だけに置かれ、キャッシュ・ファイル・ログに残らないか。

## I. 危険な関数

`Grep` で `\beval\(|\bexec\(|pickle\.load|joblib\.load|subprocess|os\.system|shell=True|yaml\.load\(|__import__|marshal` を検索する。
ユーザー入力・AI の出力・アップロードされたファイルがこれらに渡っていたら **高**。使っていなければ「該当なし」。

## J. 料金・使いすぎ

1. 生成の回数制限・1 回あたりの上限（`max_tokens`、入力の文字数）があるか。
2. LLM サービスで、無料枠を超えると課金される設定（請求先の登録・有料プラン）にしているかはユーザーに聞く。
   - 無料枠だけなら、上限で止まるだけなので **低**。
   - 課金が有効で、公開している・認証がないなら **高**（他人に使われて請求される）。
3. 予算アラートや利用上限（サービスのダッシュボードで設定するもの）をしているか聞き、していなければ勧める。設定はユーザー自身が行う。
4. ループや自動再実行（`st.rerun()` の連続、ページ表示のたびの生成など）で、意図せず何度も API を呼んでいないか → **中**。

## K. 依存パッケージ

1. `requirements.txt` などのバージョン指定が `>=` だけか、固定（`==`）か。`>=` だけなら **低**（再インストールのたびに違うバージョンが入る）。固定するかは提案に留める。
2. 入っているバージョンは `<仮想環境の python> -m pip list` で確認する。
3. 既知の脆弱性は `pip-audit`（PyPA が公開している公式ツール）で調べられる。
   - 入っていなければ、**インストールせずに提案だけ**する。入れるときはユーザーの許可を取り、そのアプリの仮想環境の中に入れる。
   - `pip-audit` はパッケージ名とバージョンを外部のデータベース（PyPI / OSV）に問い合わせることも伝える。
   - 使えない場合は「既知の脆弱性は確認していません」と書く。記憶にある脆弱性情報で「安全」「危険」と断定しない。

## L. データの扱い（個人情報・外部への送信）

1. 入力された文章は LLM サービスに送られる。会社の情報や個人情報を入れる使い方かをユーザーに聞く。
   入力内容が学習に使われるかどうかは、サービスとプラン（無料 / 有料）で違う。確認していなければ「各サービスの利用規約で確認してください（未確認）」と書き、断定しない。
2. 会話や生成履歴をファイル・DB に保存しているか。保存しているなら、保存場所・誰が見られるか・消す方法があるか → 複数人で使うなら **中**。
3. ログに入力・出力の全文を残していないか → 個人情報を扱うなら **中**。
